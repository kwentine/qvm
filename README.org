#+TITLE: QVM: networked QEMU virtual machines on a Linux host

A small set of helpers to run QEMU VMs on a shared bridge,
with DHCP, DNS and internet access.

* Installation
#+begin_src sh
  sudo make install       # host network, as root
  make install-helpers    # helper scripts, as yourself
#+end_src

This installs:
| What                                    | Where                                                      |
|-----------------------------------------+------------------------------------------------------------|
| Bridge definition (NetworkManager)      | =/etc/NetworkManager/system-connections/qvm0.nmconnection= |
| dnsmasq and nftables configuration      | =/etc/opt/qvm=                                             |
| systemd units (linked with =systemctl=) | =/etc/opt/qvm/systemd=                                     |
| Helper scripts (=make install-helpers=) | =~/.local/bin=                                             |

VM disks, base images and cloud-init seeds are searched in =~/.local/share/qvm=
(or =$QVM_DATA_DIR=), and configuration in =~/.config/qvm= (or =$QVM_CONFIG_DIR=).

* Network
Bring up the =qvm0= bridge (=10.42.0.1/24=).
NAT to the internet and =dnsmasq= serving DHCP and DNS for the =qvm0.lan= domain
start and stop with it.
On a host without NetworkManager, see [[file:docs/net.org::*Bridge][creating the bridge by hand]].
#+begin_src sh
  nmcli connection up qvm0      # down to stop
  # Inspect
  ip addr show qvm0
  resolvectl status qvm0
  journalctl -b -u qvm-dns.service
#+end_src

** Firewall
QVM keeps its rules in its own =inet qvm0= table ([[file:config/qvm0.nft]]), loaded by =qvm-nat.service=:
- masquerade traffic from the VMs to the outside world;
- drop new connections /into/ =qvm0= from any other interface: VMs can reach out, nobody can reach in.

*** Input
If your firewall drops incoming packets by default, allow DHCP and DNS from the VMs to =dnsmasq= on the host:
#+begin_src
  iifname "qvm0" udp dport { 53, 67 } accept
  iifname "qvm0" tcp dport 53 accept
#+end_src

*** IP forwarding
For the host to route the VMs' packets, =qvm-nat.service= enables IPv4 forwarding
(=net.ipv4.ip_forward=1=) when the bridge comes up. Like [[https://docs.docker.com/engine/network/firewall-nftables/#ip-forwarding][Docker]], it never turns it off:
other tools may rely on it.

* Creating virtual machines
- Add =qcow2= images that serve as VM templates to =~/.local/share/qvm/templates=:
#+begin_src sh
  mkdir -p ~/.local/share/qvm/templates
  cp ~/Downloads/rhel-10.0-x86_64-kvm.qcow2 ~/.local/share/qvm/templates
#+end_src

- Create a VM disk named =node=, as an overlay of a template:
#+begin_src sh
  qvm-create -b rhel-10.0-x86_64-kvm -s 20G node
#+end_src

- Optionally, build a =cloud-init= seed for the VM from =~/.config/qvm/user-data/node.yaml=
  (see [[file:config/user-data/rhel.example.yaml]]):
#+begin_src sh
  qvm-localds node
#+end_src

- Optionally, set VM parameters in =~/.config/qvm/machines/node=:
#+begin_src sh
  smp=2       # CPUs (default: 4)
  m=4G        # memory (default: 8G)
  cdrom=rhel-10.0-x86_64-dvd   # ISO in ~/.local/share/qvm/iso
  # mac=52:54:00:12:34:56      # default: derived from the VM name
#+end_src

* Running virtual machines
#+begin_src sh
  qvm-run node          # foreground
  qvm-run -d node       # in the background
  qvm-run -n node       # dry run: print the qemu command line
#+end_src

The VM serial console and QEMU monitor are multiplexed on a pty mentioned in the output of =qvm-run=.
To attach a terminal to it (=C-a c= switches between console and monitor):
#+begin_src sh
  foot --pty /dev/pts/3
#+end_src

Alternatively, SSH to the VM, assuming cloud-init authorized your key:
#+begin_src sh
  ssh -i ~/.config/qvm/ssh/id_ed25519 root@node.qvm0.lan
#+end_src

To stop a VM started in the background:
#+begin_src sh
  kill "$(cat ~/.local/share/qvm/run/node.pid)"
#+end_src

** As systemd user services
=make install-helpers= also installs a template unit, =qvm-machine@.service=, that runs =qvm-run NAME=:
#+begin_src sh
  systemctl --user start qvm-machine@node       # stop, status, enable (start at login)...
  journalctl --user -u qvm-machine@node         # QEMU output, including the console pty
#+end_src
- Stopping the unit kills QEMU at once, like pulling the power plug:
  shut the guest down from inside first when it matters (=ssh node poweroff=).
- The user manager does not see your shell's environment: set =QVM_DATA_DIR= or =QVM_CONFIG_DIR=
  in =~/.config/environment.d/qvm.conf= (takes effect at next login).
- User services stop when you log out, unless you let them linger: =loginctl enable-linger=.
