#+TITLE: QVM Networking

I record here the objectives that guided the networking design.

* Objectives
- Connect guests to a bridge =qvm0= on the host, as if plugged into the same switch.
- Give guests internet access by routing and masquerading their packets through the host.
- Give guests stable names: =cp.qvm0.lan= resolves from the host and from other guests.

| Item         | Value                                        |
|--------------+----------------------------------------------|
| Bridge       | =qvm0=, host address =10.42.0.1/24=          |
| DHCP range   | =10.42.0.10= – =10.42.0.100=                 |
| Domain       | =qvm0.lan= (guests), =qvm.lan= (virtual IPs) |
| DNS and DHCP | =dnsmasq= listening on =qvm0=                |

* The components
| Component                    | Provided by                               | Activation                 |
|------------------------------+-------------------------------------------+----------------------------|
| Bridge and DNS configuration | [[file:../config/qvm0.nmconnection][NetworkManager keyfile]]                    | =nmcli connection up qvm0= |
| NAT                          | [[file:../config/qvm0.nft][nftables table]] + =ip_forward= on the host | =qvm-nat.service=          |
| DHCP and DNS server          | [[file:../config/dnsmasq.conf][dnsmasq]]                                   | =qvm-dns.service=          |
| Plugging VMs to the bridge   | =qemu-bridge-helper=                      | When a VM is created       |

The bridge is the on/off switch.
=udev= publishes every network interface as a systemd device unit,

Creation of the =qvm0= interface brings =qvm-dns.service= and =qvm-nat.service= up,
as dependencies of the dynamically created =sys-subsystem-net-devices-qvm0.device= systemd unit that appears.

#+begin_src sh
  systemctl list-dependencies sys-subsystem-net-devices-qvm0.device
#+end_src

** Bridge
A Linux bridge is a virtual switch.
=make install= declares it in a NetworkManager keyfile, [[file:../config/qvm0.nmconnection]],
which conveniently also handles the DNS configuration.

To create the bridge manually instead:
#+begin_src sh
  sudo ip link add name qvm0 type bridge
  sudo ip addr add 10.42.0.1/24 dev qvm0
  sudo ip link set dev qvm0 up
#+end_src

Since =qvm-dns.service= and =qvm-nat.service= are brough up by the =qvm0= interface appearing, they will start with this method too.

Then to configure DNS resolution:
#+begin_src sh
  sudo resolvectl dns qvm0 10.42.0.1
  sudo resolvectl domain qvm0 qvm0.lan '~qvm.lan'
  sudo resolvectl default-route qvm0 no
  sudo resolvectl llmnr qvm0 no
  sudo resolvectl dnssec qvm0 no
#+end_src

To tear down the bridge:
#+begin_src sh
  sudo ip link delete qvm0
#+end_src

When a VM starts, =qemu-system-x86_64 -nic bridge,br=qvm0= runs the setuid =root= =qemu-bridge-helper=,
which creates a TAP device and plugs it into the bridge.
This is how an unprivileged user can attach VMs to a bridge created by root.

** Routing and NAT
Guests use the host (=10.42.0.1=) as their gateway. For the host to relay their to the internet:
- IPv4 forwarding must be enabled: =qvm-nat.service= sets =net.ipv4.ip_forward=1= when the bridge comes up,
  and leaves it on (Docker or libvirt behave similarly)
- Packets leaving through another interface are masqueraded (source NAT to the outgoing interface).

The rules live in their own =inet qvm0= table, so they can be inspected and removed independently:
#+begin_src sh
  sudo nft list table inet qvm0
#+end_src

I have =nftables.service= enabled on my host, which flushes the /whole/ ruleset when it stops or reloads.
So =qvm-nat.service= follows through =PartOf= and =ReloadPropagatedFrom=, to load the =qvm0= table again.

** DHCP and DNS
=dnsmasq= runs on the =qvm0= interface, providing DHCP and DNS.
If the VMs communicate their hostname in DHCP queries,
=dnsmasq= conveniently create scorresponding DNS entries:
thus, while a host =node= may not always get the same IP address, =node.qvm0.lan= accurately resolves.

On the host, =systemd-resolved= sends queries for =qvm0.lan= and =qvm.lan= to =dnsmasq=, and only those.
=qvm0.lan= is also a search domain, meaning that it will be used to complete unqulified host names, so that =ssh node= works.

To view =dnsmasq= logs:
#+begin_src sh
  journalctl -b -f -u qvm-dns.service
#+end_src
